# data/ — committed, hand-authored RPG tables (Phase 0 shape)

This directory is the **source of truth** for dagger-rpg tables that later phases will own.
It is *not* generated. `content/` is generated by `scripts/regenerate.sh` and is git-ignored-ish
for derived artifacts; `data/` is committed and reviewed.

## Convention (6683)

- File format: **JSON** (`serde_json`) — matches the engine's existing `content/**/*.json` and avoids a new RON dep at Phase 0. RON/JSONC with comments may be revisited if tables grow unwieldy, but JSON keeps tooling trivial.
- Each table is a single JSON file with a `schemaVersion` and typed arrays: `data/stats.json`, `data/weapons.json`, `data/armor.json`, `data/monsters.json`, `data/leveling.json`, etc.
- Rust side: `dagger-rpg/src/lib.rs` exposes `#[derive(Deserialize)]` structs + pure `fn` formulas (e.g. `max_health`, `attack_roll`). Tests load `data/*.json` via `include_str!` and assert against DFU-known values (see docs/daggerfall-formats.md) — no inline magic numbers in `dagger-runtime` call sites.
- Copy, don't import: patterns may be *copied* from `../rusty-engine-demo`, `../rusty-d20`, `../rusty-roguelike` with a provenance comment, never as `path`/`git` deps. See docs/companion-reuse.md § “Copy-don't-import rule”.
